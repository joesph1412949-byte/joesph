# 可视化策略选股网页 — 设计文档

日期：2026-08-11
状态：已获用户批准（2026-08-11）

## 1. 背景与目标

用户有一套完整的量化选股模型（首板/妖股/势能/节点四模型 + 24 因子评分），希望做一个**可视化网页**：
- 用 xtquant 数据自动计算能算的因子
- 网页上手动填写 xtquant 拿不到的因子
- 展示市场环境、候选股评分、单股K线+因子明细、模型对比

## 2. 数据能力边界（实测确认）

| 数据 | xtquant个人版 | 用途 |
|------|:---:|------|
| 个股日线K线(开高低收/量) | ✅ | 均线/量能/涨停/突破 |
| 实时全市场盘口(get_full_tick) | ✅ | 封单强度/涨停确认/成交额 |
| 行业板块成分股 | ✅ | 板块共振 |
| 两市成交额 | ✅ 可算 | N5 |
| 连板高度/晋级率 | ✅ 可算 | N2/N4 |
| 涨停指数 880368/883979 | ❌ | N1/N3 |
| 财务数据(市值/流通股本) | ❌ 空 | F3/Y1 |
| 龙虎榜/游资席位 | ❌ 无接口 | Y7 |
| 北向/融资余额 | ❌ 无接口 | S5 |
| 概念板块标签 | ❌ 无概念板块 | F7/Y5 |

## 3. 架构

本地 Flask 交互页，浏览器访问 localhost:5000。

```
┌─ 浏览器 ────────────────────────────────────┐
│  仪表盘 | 候选列表 | 单股详情 | 模型对比      │
└──────────────┬──────────────────────────────┘
               │ HTTP (Flask)
┌──────────────▼──────────────────────────────┐
│  Flask 后端 (Python)                          │
│  ├─ /api/screen      → 先判环境, 达标才选股   │
│  ├─ /api/manual      → 保存手填因子得分       │
│  └─ 数据层                                     │
│     ├─ xtdata实时行情   → 涨停/封单/成交额    │
│     ├─ 日线K线          → 均线/量能/突破     │
│     ├─ 行业板块          → 板块共振            │
│     └─ manual_factors.json → 手填因子持久化   │
└──────────────┬──────────────────────────────┘
               │ 启动时连接 QMT miniQMT (58610)
               ▼
            QMT (行情数据源)
```

关键设计：
- 后端启动时连一次 xtdata，页面操作间保持连接
- 手填因子存 `manual_factors.json`，重新选股时自动合并（自动算 + 上次手填）
- 前端用原生 JS + ECharts 渲染，不引入复杂前端框架

## 4. 页面结构

四个页面模块（顶部导航切换）：

### ① 市场环境仪表盘
- 节点模型 5 因子（N1-N5）得分卡片，N1/N3 数据受限标黄可手填
- 情绪阶段判定（冰点/回暖/高潮/退潮）+ 策略建议
- 两市成交额、全市场涨停家数、最高连板高度

### ② 候选股评分列表
- 表格：代码/名称/首板分/妖股分/势能分/综合分/组合等级(A-E)/关键命中因子
- 按综合分排序，A/B 类高亮
- 每行可点击 → 单股详情

### ③ 单股详情 + 因子明细
- 左侧：K线图（ECharts candlestick），标注涨停日、60日均线、突破位
- 右侧：24 因子逐项，自动算的显示得分来源，受限的显示手填输入框
- 填完保存即时重算总分

### ④ 模型对比图
- 三模型评分条形图/雷达图
- 因子命中分布
- 池内 A/B/C 类股票数量

### 交互流程
```
点"开始选股" → 后端先算节点模型
  ├─ 环境达标 → 扫全市场 → 出候选列表
  └─ 环境不达标 → 提示"环境不允许, 空仓等待", 停住
进单股详情 → 手填受限因子 → 保存 → 重算该股综合分
```

## 5. 模型实现（数据映射）

### 5.1 评分融合（用户已确认）

- 权重修正为 100%：首板30% + 妖股30% + 势能25% + 节点15%
- 综合分 = 加权和
- 三套规则并用：
  - 强弱区间：极强(节点5+任一模型≥6)→仓位75% / 强(节点≥4+模型≥5)→50% / 中等(节点≥3+模型≥5)→30% / 弱→观察空仓
  - A-E 组合分级：A(节点≥4+首板≥6) / B(节点≥4+妖股≥6) / C(节点≥4+势能≥6) / D(节点≥3+任一模型≥5) / E(空仓)
- 节点模型既计入综合分，又是环境门槛（先判环境达标才选股）

### 5.2 因子数据映射

自动计算（xtquant 数据）：

| 因子 | 数据来源 | 实现要点 |
|------|---------|---------|
| F1 首板确认 | 日线K线 | 近20日无涨停 且 今日首次涨停 |
| F2 早封板 | 实时盘口+分钟线 | 首次封板时间≤10:00 |
| F3 封单强度 | 实时盘口(替代) | 封单/成交额比, 可手填 |
| F4 板块共振 | 行业板块+实时 | 所属行业当日涨停家数≥3 |
| F5 量价堆积 | 日线K线 | 近20日≥5天量>5日均量×1.5 |
| F6 大盘配合 | 上证指数K线 | 站上20日均线或连两日放量涨 |
| Y3 倍量突破 | 日线K线 | 涨停日量≥前5日均量×3 |
| Y4 均线多头 | 日线K线 | 5/10/20粘合转多头发散+站上60日 |
| S2 量价堆积密度 | 日线K线 | 近60日≥20天量>均量1.5且价格10%内震荡 |
| S3 最小阻力 | 日线K线 | 放量突破60/120日线,回踩不破 |
| S4 均线系统 | 日线K线 | 60/120/250多头排列+斜率向上 |
| S6 板块共振强度 | 行业板块 | 板块指数上升趋势+≥3只走强 |
| N2 情绪周期 | 全市场数据 | 涨停家数+连板高度+晋级率推算 |
| N4 连板高度 | 全市场数据 | 最高连板≥5 或晋级率>25% |
| N5 成交额 | 全市场数据 | 两市成交额≥2万亿 |
| N1 涨停指数(替代) | 全市场数据 | 用涨停家数相对5日均线替代880368 |
| N3 首板溢价(替代) | 全市场数据 | 用昨日涨停股今日平均涨幅替代883979 |

| 因子 | 受限原因 |
|------|---------|
| F7 题材新颖 | 无概念板块 |
| Y1 小市值 | 无财务数据 |
| Y2 筹码干净 | 无股东/研报数据 |
| Y5 多概念 | 无概念标签 |
| Y6 事件催化 | 无公告数据 |
| Y7 游资现身 | 无龙虎榜接口 |

| S7 基本面催化 | 无订单/政策数据 |

### 5.3 性能设计

- 全市场约 5000 只，实时盘口一次拉全（已验证 0.03s）
- 日线K线逐只拉慢 → **只对"今日涨停池"算详细因子**（约几十只），不扫全部5000只K线
- 首次选股前下载所需K线数据并缓存

## 6. 技术栈

- 后端：Python 3.12 + Flask + xtquant
- 前端：原生 HTML/JS + ECharts（CDN 或本地）
- 数据持久化：JSON 文件（manual_factors.json、选股结果快照）
- 部署：本机 localhost 运行

## 7. 错误处理

- xtdata 连接失败 → 页面提示"QMT未连接/未开启miniQMT"，不崩溃
- 数据拉取部分失败 → 该股票因子标"数据缺失"，不阻塞其他股票
- 手填输入校验：只接受 0/1，非法输入提示
- 重新选股时保留上次手填值，避免重复填写

## 8. 范围边界（非目标）

- 不做真实下单（发单仍走现有文件桥策略）
- 不做盘中实时自动刷新（手动点按钮触发选股）
- 不做多用户/权限
- 不做移动端适配（优先桌面浏览器）
