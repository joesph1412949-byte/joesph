# 策略打分重构 + 手填因子自动化 (v2) 设计

日期:2026-08-11
状态:已通过设计评审(节点=总开关 / 绝对阈值分级 / 东财自动化),待实现

## 背景与问题

对 v1(`2026-08-11-strategy-visual-web-design.md`)实测后的三个缺陷:

1. **候选池 = 当日全部涨停股,无个股门槛。** [screen.py](../strategy_web/screen.py) 把当天所有涨停股直接打分展示,`ENV_THRESHOLD` 只决定"要不要选股",不缩小个股范围。且 v1 的 A–E 分级门槛过严(如 A 需首板≥6 且节点≥4),正常行情下全部落 E,分级失去区分度。
2. **节点因子被以常数形式注入个股综合分。** N1–N5 是市场级因子,却通过 `factors.update(market_factors)` 逐股注入,导致所有股票节点分完全相同(实测 node=4×60),综合分含市场统一水分,排名失真;用户误以为是个股属性。
3. **9 个手填因子人工负担重。** F7/Y1/Y2/Y5/Y6/Y7/S1/S5/S7 需在网页逐个填 0/1,且多数可从东方财富公开接口自动计算。

## 目标

- 节点回归"所有模型的前提"语义:**总开关**,只当市场门槛,不进个股综合分
- 增加**个股达标门槛**,真正缩小候选池
- A–E 分级改为**绝对阈值**,不依赖节点分
- 用**东财公开 API** 自动计算可自动的手填因子,手填缩到最少
- 全部改动保持:离线可测、QMT 断连不崩、失败回退(fail-open)

## 设计

### 1. 节点 = 总开关(不再进个股综合分)

- `ENV_THRESHOLD = 3` 保留:[screen.py](../strategy_web/screen.py) 中节点分 < 3 → 空仓,一只不选(现有行为)
- **删除** [screen.py](../strategy_web/screen.py) 中 `factors.update({k: v.get("score", 0) for k, v in market_factors.items()})` 这一行 —— 市场因子不再注入任何个股
- 市场因子 N1–N5 仍每次 run 计算一次,用途只剩两个:① `ENV_THRESHOLD` 闸门判断;② 市场环境仪表盘整屏展示(它是"市场徽章",不是个股属性)
- 个股因子表不再出现 N1–N5 行

### 2. 综合分公式

```
综合分 = 0.30 × 首板分 + 0.30 × 妖股分 + 0.25 × 势能分
上限   = 0.30×7 + 0.30×7 + 0.25×7 = 5.95
```

- 节点 15% 权重移除,保留 30/30/25 相对权重(不归一化,排序不受缩放影响)
- 综合分仅用于候选内排序,不再用于任何门槛

### 3. 个股达标门槛(真正选股)

- 新增配置常量 `CANDIDATE_MIN_MODEL = 3`(screen.py 顶部,与 `ENV_THRESHOLD` 并列)
- **候选条件**:最强模型分(首板/妖股/势能任一)≥ `CANDIDATE_MIN_MODEL` 才进候选清单
- 低于门槛的涨停股**不进清单**(区别于 v1 的"全部展示")
- 当前临时设 3(实测今日留 1 只);后续可调 4 收紧
- 门槛判定用**去除节点后的模型分**(即纯 F/Y/S 因子)

### 4. A–E 分级(绝对阈值,节点退出)

| 等级 | 规则 |
|------|------|
| A | 最强模型 ≥ 6 |
| B | 最强 ≥ 5 且 次强 ≥ 3 |
| C | 最强 ≥ 4 |
| D | 最强 ≥ 3(= 门槛线) |
| E | 未过门槛,不展示 |

- "最强模型" = max(首板, 妖股, 势能);"次强" = 三个模型分中第二大
- 市场环境由 `ENV_THRESHOLD` 单独把关,不再参与个股评级
- 候选清单里不会出现 E(过门槛至少 D);`classify_market` 情绪阶段逻辑不变

### 5. 手填因子自动化(东方财富)

#### 5.1 自动化清单(探针确认后最终定)

| 因子 | 含义 | 拟规则 | 数据源 |
|------|------|--------|--------|
| Y1 小市值 | 流通市值 | 流通市值 < 80 亿 | 现有 `float_mv`,零成本 |
| Y5 多概念 | 概念标签数 | 概念标签 ≥ 3 | 东财涨停池/概念接口 |
| F7 题材新颖 | 题材是否新 | 涨停原因/概念近 N 日首次出现 | 东财涨停池历史 |
| Y7 游资现身 | 龙虎榜 | 近 N 日龙虎榜有该股(净买或知名席位) | 东财龙虎榜接口 |
| S5 机构流入 | 融资/北向 | 融资余额近 5 日增长 或 北向增持 | 东财融资/北向接口 |
| Y6 事件催化 | 利好公告 | 近 N 日利好公告(业绩预增/中标/重组等关键词) | 东财公告接口 |
| Y2 筹码干净 | 股东户数 | 股东户数环比下降 | 东财股东户数接口 |
| S7 基本面催化 | 研报/业绩 | 近 N 日研报/业绩预告(探针后定) | 东财研报接口 |
| S1 产业趋势 | 产业趋势 | **保留手填** | — |

- **先做数据探针**(沿用 v1 的 N1/N3/N4 做法):确认各接口真实返回的字段与格式,再定最终清单与阈值;拿不到的保持手填
- N 值(如"近 N 日"、"80 亿"、"≥3")全部做成模块常量,便于调参

#### 5.2 架构

- 新模块 `fundamental.py`:`FundamentalFeed` 类,每个因子一个方法(如 `fetch_concepts(code)`、`fetch_dragon_tiger(code)`),返回 `{"score": 0/1, "note": str}` 或抛错
- **可注入假实现**(构造参数),与 v1 `EastMoneyFeed` 同模式,便于离线测试
- **失败一律 fail-open**:某因子接口失败 → 该因子回落手动输入,绝不影响整屏(与 v1 的 em 兜底一致)
- **按日缓存**(`code + 交易日 → JSON` 文件):当天首次运行慢(估 +10~30 秒),之后秒回
- [screen.py](../strategy_web/screen.py) 集成:自动因子算完后调 `FundamentalFeed` 补齐可自动因子;仍可手填覆盖
- `MANUAL_FACTORS`([manual_store.py](../strategy_web/manual_store.py))缩减到 `S1` + 探针未确认项

### 6. UI(本轮最小改动)

- 候选表去掉"节点"列(改为市场环境徽章,仅仪表盘展示)
- 个股详情因子表标注来源:**QMT 自动 / 东财自动 / 手填**(HTML 属性或徽标)
- 本轮不做大规模美化(v1 的布局/蜡烛图保留)

### 7. 测试

- **models**:新分级阈值(A/B/C/D 边界)、"最强/次强"计算单测
- **screen**:门槛过滤生效、节点不注入个股、`CANDIDATE_MIN_MODEL` 可配、环境不达标仍空仓
- **fundamental**:各因子 0/1 分支 + fail-open + 按日缓存,全部 mock HTTP(沿用 [test_eastmoney.py](../strategy_web/tests/test_eastmoney.py) 模式)
- **更新旧测试**:`test_screen` 中断言节点注入的用例改为断言"不注入";`test_models` 分级用例按新阈值重写

## 风险与已知

- 东财接口字段名需探针实测确认;若个别接口不可用,该因子保持手填,不阻塞其余
- 非交易日 / 早盘数据不完整时,东财数据可能为空 → fail-open 回落手填
- 缓存按交易日键控;跨日必须取新数据,避免用旧缓存
- `CANDIDATE_MIN_MODEL = 3` 为临时值,可随时上调
