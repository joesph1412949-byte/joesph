# 首板盘后深度拆解模块 设计（2026-09-18）

> 状态：待用户评审
> 模块：`prism/first_board_review.py`
> 定位：**观察层（不进因子打分）**，为手写因子提供结构化印证实证

---

## 1. 背景与目标

用户明确的分工界面：

| 时段 | 谁 | 做什么 |
|---|---|---|
| 09:15–10:00 | 用户 | 竞价+开盘执行交易，只选最强方向能涨停的首板；10:00 后盘中不动手 |
| 收盘后 | agent | 对当日**每一个首板**彻底拆解，分析到无法再拆为止 |

用户会**坚持手写因子，一笔一笔印证**。本模块的职责不是替用户做决策，而是：
1. 把当日首板的事实证据**尽量自动抓全**（用户明确要求"用 prism 本身自带的数据接口"，不手填 JSON）
2. 用统一口径把五维拆解结构化输出，让用户能拿它对照手写因子

**成功标准**：用户拿到一份 `docs/reports/首板拆解_YYYYMMDD.md`，每只首板五维展开、每个数字都有来源标注，可以直接在上面做手写因子的印证与淘汰。

---

## 2. 数据来源（关键设计决策）

用户要求**优先用 prism 自带接口自动抓**。探索后确认的可复用资产：

| 维度 | 数据 | 来源 | 现状 |
|---|---|---|---|
| 涨停池 | `{code, boards}` | `zt_history.qmt_zt_feed(date)` | ✅ 现成，O(1) 索引 |
| 首板筛选 | `boards == 1` | 同上 | ✅ 现成 |
| **封板质量** | 首封时间/开板次数/一字板/板上量额 | **`bt_intraday.features_for(code, day)`** | ✅ **关键发现**：已能用 1m K 线纯计算还原盘面 |
| 量能结构 | 当日量额 vs 前 N 日均量 | `data.py` / kline 缓存 | ✅ 现成 |
| 板块归属 | code → 行业 | `datasource` sector_map | ✅ 现成 |
| 板块内涨停家数 | 同行业当日涨停计数 | 涨停池 + sector_map 自算 | ✅ 可算 |
| 流通市值 | float_mv | `data.py`（QMT→tdx 兜底，已接线） | ✅ 现成 |
| 封单金额（buy1 队列） | 盘口厚度 | 实时 tick `bidVol[0]` | ⚠️ **仅实时可得**，盘后不可复现 |

**唯一真正的缺口 = 封单金额（buy1 队列厚度）**。这条只在实盘/模拟盘实时 tick 里有，盘后无法复现。

**处置（不造假原则）**：
- 模块**不猜**封单金额。缺 → 该字段标 `"未知"` 并注明"盘后不可复现，需实时快照"。
- 若用户当日盘中曾跑过守护/快照并留下了 tick，则从快照读；否则留空。
- **封板质量用 1m 特征为主证据**（首封时间、开板次数、板上量额），这些是可复现的等价信息，比不可得的队列更硬。

> 这一条落实 MEMORY 里反复出现的约定：**拿不到就是"未知"，绝不推测**（同 09-16「不造假」口径）。

## 3. 架构

三层，每层单一职责、可独立测试：

```
┌─ ① 采集层 collect(day) ────────────────────────────────┐
│  输入: day "YYYYMMDD"                                   │
│  1. zt_history.qmt_zt_feed(day) → 涨停池                │
│  2. 筛 boards == 1 → 首板清单                           │
│  3. 逐只: bt_intraday.features_for() → 封板盘面特征      │
│  4. 逐只: 日K → 当日量额 / 前5日均量 / 前20日振幅        │
│  5. 逐只: sector_map → 板块; 同板块当日涨停家数自算      │
│  6. 逐只: float_mv（QMT→tdx 兜底）                      │
│  7. 封单金额: 尝试实时快照, 拿不到 → None                │
│  → List[BoardRecord]（每个字段带 source: auto|manual|unknown）│
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ ② 覆盖层 apply_manual(records, manual) ────────────────┐
│  manual = 可选 dict（用户偶尔手补，如封单金额）           │
│  手填优先，覆写后 source 标 manual                       │
│  来源可以是: 对话口述由 agent 写入 / 一个 JSON 文件        │
│  非必需路径 —— 全部可自动时不需手填                      │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─ ③ 分析层 analyze(record) ──────────────────────────────┐
│  五维，每维: 结论 + 依据(逐条带数字) + 分维评分           │
│  A 封板质量  first_seal_hm / open_times / one_word / 板上额占比 │
│  B 板块共振  板块内涨停家数 / 板块是否最强方向            │
│  C 量能结构  量比 / 换手 / 与前均量对比 / 是否放量        │
│  D 资金行为  板上量额特征 / (封单金额若有) / 龙虎榜若有    │
│  E 产业逻辑  板块定位 / 是否新题材 / 联动关系             │
│  → 五维加权总评分 0-100 + 置信度标签(高/中/低/跟风脉冲)   │
└─────────────────────────────────────────────────────────┘
```

## 4. 综合评分口径（用户要求"给出总评分"）

五维加权，权重**先给初值，标明可校准**（沿用 F3 `BT_SEAL_RATIO_T` 的做法：常量集中、校准后只改一处）：

| 维度 | 权重 | 说明 |
|---|---|---|
| A 封板质量 | 0.35 | 首板核心。早封/不开板/一字 = 高分 |
| B 板块共振 | 0.25 | 板块内涨停家数越多越强 |
| C 量能结构 | 0.20 | 放量适度最佳，过度放量=接力盘重 |
| D 资金行为 | 0.15 | 依据可得字段动态计权（封单缺失时该维降权，总权重归一） |
| E 产业逻辑 | 0.05 | 主观维，默认中性分 |

**缺失维度处理**：某维数据不可得 → 该维权重从分母剔除，其余维归一化，并在输出注明"X 维数据缺失，未计入"。**绝不用 0 分冒充"已评估"**（吸取 MEMORY #16 假覆盖率教训）。

输出置信度标签：
- `高`：五维齐 + 总分 ≥ 75
- `中`：总分 55–75
- `低`：总分 35–55
- `跟风脉冲`：板块共振极弱（板块内仅 1 只涨停）或 板上量额占比异常高

## 5. 产出

### 5.1 CLI
```bash
python -m prism.first_board_review --date 20260918            # 打印 + 落 JSON
python -m prism.first_board_review --date 20260918 --report   # 额外生成 md 报告
python -m prism.first_board_review --date 20260918 --manual path/to/manual.json
```

### 5.2 落盘
- JSON：`runtime/state/first_board_review_YYYYMMDD.json`（结构化全量，供后续分析）
- 报告：`docs/reports/首板拆解_YYYYMMDD.md`（人读版）

### 5.3 报告形态（每只首板一段）
```markdown
## 600xxx.SH 某股票 ｜ 总评 82 (高)

| 维度 | 评分 | 关键依据 |
|---|---|---|
| 封板质量 | 90 | 首封 09:35、零开板、板上额占比 2.1% |
| 板块共振 | 85 | 所属「半导体」当日 7 只涨停（板块最强） |
| 量能结构 | 72 | 量比 2.3，为前5日均量 2.4 倍 |
| 资金行为 | 78 | 板上量额 1.2 亿，占流通市值 1.8% |
| 产业逻辑 | 70 | 板块处于主升期（sector_stage 判定） |

**拆解**：...
**存疑**：封单金额不可得（盘后无法复现 buy1 队列）
```

## 6. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 涨停池索引陈旧/空 | 沿用 `zt_history` 的 fail-closed，返回空 + warning，不产出空报告冒充成功 |
| 1m 特征缺失（早于 2025-09-15 或采集缺口） | 封板质量维标"数据缺失"，**降权而非给 0** |
| QMT 离线 | 日K 走 tdx 降级；两者都挂 → 该股标"数据不足"，如实说明 |
| 当日非交易日/无首板 | 明确输出"当日无首板"，不是空文件 |
| 板块映射缺失 | 板块维缺失，注明 |

## 7. 测试（TDD）

`prism/tests/test_first_board_review.py`：
1. 纯函数测试：`analyze()` 喂构造 record → 断言各维评分与总评分（**零 IO**）
2. 缺失维度降权：封单缺失时总权重归一化正确、不出现 0 分冒充
3. `collect()` 用注入的假 feed（zt/intraday/kline）→ 断言首板筛选只看 boards==1
4. 手填覆盖：manual 优先、source 标注正确
5. 报告生成：字段齐全、缺失字段如实标注"未知"

**不触网、不依赖 QMT 在线**（沿用项目 conftest 约定）。
