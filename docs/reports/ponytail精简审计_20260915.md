## 四、明确「不算臃肿」的部分（审计保留）

- 多源降级链（QMT → 通达信 → 东财 → 新浪/FRED）与 fail-open：规格要求，删了就失去断源自愈能力
- `_tail_stale` / `_shrink_suspicious` / `_merge_tail` / `_atomic_pickle` / 看门狗超时防护：缓存合并与原子写语义，手册保护
- `# ponytail:` 标记的 4 处刻意延后项：属已记录债务，非发现
- 测试侧假桩：与被测源一一对应，无膨胀
- 根目录 11 个 `.bat` 双击入口：各有明确职责（做T 的 6 种运行形态 + 守护 + 监控台），非冗余

## 五、执行原则

1. **删前先证死**：每条 `delete` 都先 `git grep` 全仓确认零生产引用（仅测试引用也会标注）
2. **删代码同步删测试**：死功能的测试本身就是死重量
3. **结构改动与行为改动分离**：本批只做删除/提取，不改任何业务判定与数值语义
4. **全程保绿**：每个文件组改完即跑该组测试，最后跑全量回归
5. **不简化受保护语义**：fail-open、原子写、缓存合并、测试离线确定性一律原样保留
