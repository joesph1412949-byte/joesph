## 二、报错与异常：定位过程与修复结果

### ① 全量测试从 518 绿崩到「21 failed + 177 errors」——真实缺陷，已修 ✅

**现象**：跑 `pytest prism/tests prism_web/tests strategy_web/tests` 时
`prism/tests/test_sector_factors.py` 整片 21 例 `UnknownFactorError: 未知因子: SEC1`。
单独跑该文件、拆对跑都正常——典型的**跨用例状态污染**。

**定位过程**（挂了临时诊断钩子打印每个测试边界的注册表规模）：
```
REGDIAG setup n=1  prism/tests/test_registry.py::test_get_factor_unknown_raises
REGDIAG setup n=1  prism/tests/test_sector_etf_map.py::test_covers_all_31_sw_industries
REGDIAG setup n=1  prism/tests/test_sector_factors.py::test_sec1_updays_hit   ← 只剩 1 个因子
```

**根因**：`test_backtest.py` / `test_registry.py` 的 autouse fixture 会 `reg.reset()`
再注册自己的测试因子；由于 pytest 的 autouse fixture 实例化顺序，
`prism/tests/conftest.py` 的还原快照**有可能在被污染之后才取到**，
于是"还原"反而把真实 36 因子库从整个 session 里抹掉 —— 之后所有依赖真实因子库的
用例（`test_sector_factors` 直接 `get_factor("SEC1")`）全线崩。

**修复**（两层防御）：
1. `conftest.py`：新增会话级"干净基线" + 哨兵 `SEC1` 检测，还原后若真实库缺席则自动补回；
2. `test_sector_factors.py`：新增 autouse fixture，**按需强制重扫真实因子库** ——
   让测试文件自足，不再依赖外部残留状态（这是根治：测试不该依赖"环境恰好对"）。

**验证**：同一沙箱条件下 `prism/tests` **469 passed / 0 failed**（修复前 21 failed）。

### ② `registry._clear_factor_bytecode` 缓存清理失败会中断因子注册——健壮性缺陷，已修 ✅

**根因**：`scan_factors(force=True)` 会先删 `__pycache__/factor_*.pyc`，
但清理代码只吞 `OSError`。沙箱安全钩子抛的是 `SystemExit`（继承 `BaseException`），
**穿透捕获 → 因子注册半途而废 → 注册表残缺**。

**修复**：字节码缓存清理是 best-effort，改为捕获 `BaseException`（`KeyboardInterrupt` 除外）。
即便删除全失败，`sys.modules` 弹栈 + 重新 import 仍会重触发装饰器，注册结果正确。
